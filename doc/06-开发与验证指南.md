# 开发与验证指南

## 1. 环境

当前源码需要：

- macOS 26+。
- Xcode 26+ / macOS 26 SDK。
- Swift 6。
- XcodeGen（验证前从 `project.yml` 重新生成工程）。
- 如要通过仓库 `build.sh` 安装运行，需要脚本中对应的 Apple Development 签名身份。

主工程没有 Swift Package、CocoaPods 或 Carthage 依赖。本文中的命令均在仓库根目录执行。

## 2. 生成工程

```sh
xcodegen generate
```

[`project.yml`](../project.yml) 是 target、[`Sources/Resources/Info.plist`](../Sources/Resources/Info.plist)、[`Sources/Resources/MeetingCaptions.entitlements`](../Sources/Resources/MeetingCaptions.entitlements) 和 build setting 的声明来源。修改构建设置时应先改它，再生成 `.xcodeproj`，避免两处漂移。生成的 `MeetingCaptions.xcodeproj` 已被 `.gitignore` 排除。

## 3. 无签名编译检查

适合 CI 或普通源码验证：

```sh
xcodebuild \
  -project MeetingCaptions.xcodeproj \
  -scheme MeetingCaptions \
  -configuration Debug \
  -derivedDataPath .build \
  CODE_SIGNING_ALLOWED=NO \
  build
```

主 target 使用 Swift 6 和 `SWIFT_STRICT_CONCURRENCY=complete`。不应用 unsafe Sendable 标注或降低检查级别解决新的并发诊断。

## 4. 单元测试

`MeetingCaptionsTests` 是 `MeetingCaptions` scheme 的 XCTest target。使用 macOS destination 运行：

```sh
xcodebuild test \
  -project MeetingCaptions.xcodeproj \
  -scheme MeetingCaptions \
  -configuration Debug \
  -derivedDataPath .build \
  CODE_SIGNING_ALLOWED=NO \
  -destination 'platform=macOS'
```

修改纯逻辑或持久化映射时，单纯构建不算完成；必须运行相关测试。

## 5. 安装运行

仓库脚本 [`build.sh`](../build.sh)：

```sh
./build.sh
```

它会：

1. 无签名编译。
2. 用硬编码的开发证书重新签名。
3. 停止桌面上既有的“同频”进程。
4. 覆盖 `~/Desktop/同频.app`。
5. 启动应用。

固定 bundle id、固定安装路径和稳定证书是为了让 TCC 权限绑定保持稳定。这个脚本带有进程停止和覆盖安装的副作用，不能当作纯编译命令；其他开发者需要先调整 `SIGN_ID`。

## 6. 首次权限验证

按顺序确认：

1. 语音识别权限已允许。
2. 麦克风权限已允许。
3. 屏幕录制权限已允许。
4. 首次语言模型资源已经下载。
5. 首次使用的英语 / 简体中文翻译方向所需语言资源已经准备。

权限与签名身份关联。频繁改变 ad-hoc 签名或运行位置可能让系统把它视作新应用。

## 8. 最小手工验证矩阵

### 8.1 实时字幕

- 仅系统音频：remote 正常，mic 关闭不创建 mine Section。
- 双路：我/对方标签不串流。
- 对方 → 我 → 对方：Section 顺序与 final commit 顺序一致。
- 两路重叠：确认当前 single-floor 串行化行为符合预期。
- 长单人发言：第 7 个 final 句子进入新 Section，翻译仍带前文。
- 噪声 partial：非 floor interim 不应抖动切段。
- 在词表 Tab 新增、删除和重复输入词条后保存并重开设置，确认内容已规范化且持久化。
- 会议进行中保存新词表不应改变当前识别器；暂停并恢复后，两路英文识别使用新词表。

### 8.2 翻译

- interim 持续增长时 UI 不积压很久。
- 旧 generation 晚返回时不覆盖新译文。
- 换人后 sealed Section 最终进入 done。
- 翻译失败时 Section 进入 failed，原文仍然可见，暂停/结束不会永久卡住。
- 英语→英语和简体中文→简体中文均不发翻译请求、不重复显示原文。
- 英语→简体中文与简体中文→英语均按所选方向显示目标语言，菜单名称固定为“英语 / 简体中文”。
- 上下文分隔符被翻译器改写时可回退到 target-only。

### 8.3 会话和历史

- start 后未说话就退出；下次启动的空记录行为合理。
- 录制中退出/崩溃，重启后最新会话作为 paused 恢复。
- 暂停期间计时不增长，恢复后连续累计。
- 同时保留多个 paused 会话并来回挂载，Section id 不冲突、不重复。
- stop 后历史行、时长、译文都已最终保存。
- 启动/恢复模型期间快速终止时，迟到 ASR/翻译不能混入后续会议。
- 模拟持久化失败时不应卸载当前会话或显示虚假成功。
- 删除非当前历史时 relationship 级联生效。

### 8.4 AI

- 未配置时实时主链路完全可用。
- 401、429、超时、非 JSON 都显示正确错误。
- 高密度提交时最多一个洞察请求在飞，结束后只补一次最新快照。
- 会后优化单批失败不抹掉其他成功批，也不覆盖原始文本。
- 翻译与同语言会议的优化 prompt 和回写字段不同；翻译 prompt 必须符合保存的语言方向。
- 超长历史输入只发送最新 6000 字符且优先保留完整行。
- 开始新会议后，旧实时洞察结果不得回写当前面板。

## 9. 当前自动化覆盖

`Tests/` 当前固定了：

1. `CaptionStore` 的 floor 切换、6 句分段、非 floor interim、restore id/上下文和 generation。
2. `TranslationBridge` 的同 Section 覆盖、跨 Section 顺序和 idle drain。
3. `MeetingHistoryStore.sync/finish` 的 upsert、stale 删除和空会议删除。
4. 洞察最新上下文窗口、strict JSON Schema 请求体和非法结构拒绝。
5. 会后优化的行数和字符分批上限。
6. 英文词表的默认值、空词表持久化、去空白和大小写不敏感去重。
7. 固定语言名称、四种源/目标组合、翻译旁路和语言对持久化值。

这些测试不触发真实音频、系统权限、Apple Translation 或网络。修改这些 I/O 边界时，必须在已签名应用中补相关人工 smoke test，并如实报告未执行的路径。
