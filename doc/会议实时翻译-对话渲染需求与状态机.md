# 一对一会议实时翻译 — 对话渲染需求与状态机

> 面向：Dev
> 目标：定义一对一实时翻译会议中，对话（section）的分段、封板、翻译渲染逻辑。
> 类型：产品设计基线；不直接等同于当前运行行为。
> 实现对照：[02-实时字幕与翻译流水线.md](02-实时字幕与翻译流水线.md)，对应源码为 [`Sources/Meeting/CaptionStore.swift`](../Sources/Meeting/CaptionStore.swift) 和 [`Sources/Meeting/CaptureCoordinator.swift`](../Sources/Meeting/CaptureCoordinator.swift)。

---

## 一、核心概念

- **Section（段）**：一段连续的、未被对方打断的单说话人语音。每个 section 归属唯一说话人，含"原文"和"译文"两部分，译文可异步追加。
- **说话人无关**：section 归属谁只取决于谁在说，不区分"我"和"对方"。谁先开口，谁就是 section 0。
- **封板**：section 停止追加新的 ASR 原文，但**允许对已有原文做修正**，且译文可继续异步完成。
- **两条正交规则**：分段（规则 A）与翻译（规则 B）相互独立，翻译状态不参与分段决策。

---

## 二、两条核心规则（正交）

**规则 A — 分段**
当说话人从"当前 section 的说话人"切换为另一人时：当前 section 立即封板，为新说话人开一个新 section。若原说话人在被打断后继续说，其续说内容也是一个**全新的 section**。

**规则 B — 翻译独立**
封板只停止追加新原文，不影响译文。该 section 的译文独立继续，直到翻译完成。**翻译状态不参与任何分段决策**，仅影响 UI 是否显示"翻译中"指示。

> 所有场景都由这两条规则推导得出。

---

## 三、场景推导（以对方先说为例，反向同理）

初始：对方说话 → section 0（对方）。

**我开始说话时：**

| 情况 | 对方状态 | 结果 |
|------|---------|------|
| 3.1 | 对方还在说（打断） | section 0 封板（译文继续）；新建 section 1 = 我；对方续说 → 新建 section 2（对方） |
| 3.2 | 对方已说完，尾巴还在翻 | section 0 封板（译文继续）；新建 section 1 = 我 |
| 3.3 | 对方已说完且已翻完 | 新建 section 1 = 我 |

> 3.2 与 3.3 在分段结构上完全相同，唯一区别是 3.2 的 section 0 仍显示"翻译中"指示。

---

## 四、边界规则（已确认）

1. **说话人无关**：模型对"我 / 对方"对称，section 0 属于先开口的一方。
2. **对称打断**：无论谁打断谁，规则完全一致。
3. **重叠排序**：发生打断时，UI 中先插入**打断方**的 section，再在其后放入**被打断方**续说的 section（即 3.1 中：section 1 我 在前，section 2 对方续说 在后）。
4. **切断句翻译上下文**：一句话被打断切成两段时，复用现有**滑动窗口机制**保证翻译上下文，避免各段独立翻译导致语义断裂。
5. **短应答/口头语（"嗯""OK""yeah"等）**：使用与普通说话**完全相同**的触发逻辑，同样会触发封板与新建 section，不做特殊处理（优先保证逻辑简单）。
6. **ASR 回改**：封板后**允许**对已识别原文进行修正（仅禁止追加新内容）。

## 五、状态定义

### 5.1 Section 生命周期状态

```
ACTIVE      正在接收该说话人的 ASR 原文，可追加、可修正
SEALED      已封板，禁止追加新原文；仍可修正已有原文；等待/进行翻译
TRANSLATING 译文异步生成中（可与 SEALED 并存）
DONE        原文冻结 + 译文完成，终态
```

> `SEALED` 与 `TRANSLATING` 是两个正交维度。实现上建议拆成两个字段：
> - `contentState`: `OPEN | SEALED`（是否还接收新原文）
> - `translationState`: `PENDING | TRANSLATING | DONE`
>
> 下文的"状态"若无歧义，指 `contentState`。

### 5.2 Section 数据结构

```
Section {
  id               : int          // 全局自增，也是显示顺序基准
  speaker          : SpeakerId    // 说话人无关，仅记录归属
  contentState     : OPEN | SEALED
  translationState : PENDING | TRANSLATING | DONE
  sourceText       : string       // 原文（OPEN 可追加/修正；SEALED 仅可修正）
  targetText       : string       // 译文（异步追加）
  startTime        : timestamp    // 用于重叠排序
}
```

### 5.3 全局控制器状态

```
IDLE          无人说话
SINGLE        仅一名说话人处于 ACTIVE
OVERLAP       两名说话人同时活跃（打断进行中）
```

## 六、Section 状态转移

```
        ┌──────────── 追加/修正原文 ───────────┐
        ▼                                       │
   [ CREATE ] ──► ACTIVE(OPEN) ────────────────┘
                     │
                     │ 触发封板（对方开始说话）
                     ▼
                  SEALED ──── 修正原文（允许） ──┐
                     │  ▲                        │
                     │  └────────────────────────┘
                     │
     翻译调度 ────────┼──────────────────────────►
                     ▼
   PENDING ──► TRANSLATING ──► DONE
                     ▲   │
                     └───┘ 译文分片追加

  终态条件：contentState == SEALED && translationState == DONE  ⇒ DONE
```

**关键：封板与翻译解耦**。封板发生在 `ACTIVE → SEALED`；翻译在 `PENDING/TRANSLATING/DONE` 维度独立推进，不阻塞分段。

---

## 七、控制器状态转移

| 当前状态 | 事件 | 下一状态 | 说明 |
|----------|------|----------|------|
| IDLE | onSpeechStart(A) | SINGLE | 新建 section(A) |
| SINGLE | onSpeechStart(B)（B≠当前说话人） | OVERLAP | 封板 A 的 section，新建 section(B) |
| SINGLE | onSpeechEnd(A) | IDLE | A 的 section 封板 |
| SINGLE | onSpeechStart(A)（同一人续说，理论上不发生） | SINGLE | 忽略/合并 |
| OVERLAP | onSpeechEnd(其中一方) | SINGLE | 另一方仍活跃 |
| OVERLAP | onSpeechEnd(两方先后) | IDLE | 全部封板 |
| OVERLAP | onSpeechStart(被打断方续说) | OVERLAP | 为续说方新建 section |

---

## 八、触发事件与转移规则

| 事件 | 条件 | 动作 |
|------|------|------|
| `onSpeechStart(spk)` | 无当前 ACTIVE section | 新建 section(spk) → ACTIVE，控制器 → SINGLE |
| `onSpeechStart(spk)` | 存在另一说话人的 ACTIVE section | ① 该 section 封板(`OPEN→SEALED`) ② 新建 section(spk) → ACTIVE ③ 控制器 → OVERLAP |
| `onAsrUpdate(spk, text)` | 该说话人 section 为 OPEN | 追加/修正 sourceText |
| `onAsrUpdate(spk, text)` | 该说话人 section 为 SEALED | **仅允许修正**已有 sourceText，拒绝新增 |
| `onSpeechEnd(spk)` | — | 标记该说话人不再活跃；若无人活跃 → IDLE，否则 → SINGLE |
| `onTranslationChunk(id, t)` | — | 追加 targetText，translationState → TRANSLATING |
| `onTranslationDone(id)` | — | translationState → DONE；若 contentState==SEALED ⇒ section DONE |

> **短应答不特殊处理**：`onSpeechStart` 对"嗯/OK/yeah"等一视同仁，同样触发封板。

## 九、打断场景推导（对应 3.1）

```
t0  对方说话           → section 0 (对方, ACTIVE)
t1  我打断
      · section 0: OPEN → SEALED（译文继续）
      · 新建 section 1 (我, ACTIVE)
      · 控制器 → OVERLAP
t2  对方续说
      · section 2 (对方, ACTIVE) 新建
t3  我说完 onSpeechEnd(我)
      · section 1 → SEALED
      · 控制器 → SINGLE（对方仍活跃）
```

**显示顺序**：严格按 `section.id` 升序。因新建顺序为"先打断方、后被打断方续说"，天然满足边界规则第 3 条（section 1 我 在前，section 2 对方续说 在后）。

## 十、分段核心伪代码

```python
def on_speech_start(spk):
    cur = active_section_of_other_speaker(spk)
    if cur is not None:
        seal(cur)                      # OPEN -> SEALED，触发翻译调度
    new_sec = create_section(spk)      # id 自增，ACTIVE/OPEN
    new_sec.startTime = now()
    update_controller_state()

def on_asr_update(spk, text):
    sec = active_section_of(spk)
    if sec.contentState == OPEN:
        sec.sourceText = merge_append_or_correct(sec.sourceText, text)
    else:  # SEALED
        sec.sourceText = correct_only(sec.sourceText, text)  # 拒绝新增
    reschedule_translation(sec)

def seal(sec):
    sec.contentState = SEALED
    schedule_translation(sec)          # 进入 PENDING

def on_translation_chunk(id, chunk):
    sec = get(id)
    sec.targetText += chunk
    sec.translationState = TRANSLATING

def on_translation_done(id):
    sec = get(id)
    sec.translationState = DONE
    # DONE 由 contentState==SEALED && translationState==DONE 自动判定
```

## 十一、翻译上下文（滑动窗口）

一句话被打断切成多段（如 section 0 尾 + section 2 头）时，翻译**不独立处理**，复用现有滑动窗口：调度某 section 翻译时，携带同一说话人相邻上文窗口，保证跨段语义连续。

```python
def translate(sec):
    context = sliding_window(sec.speaker, before=sec)   # 复用现有机制
    submit(source=sec.sourceText, context=context)
```
